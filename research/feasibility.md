# Review-analysis extension: feasibility constraints

Checked 1 October 2026. Target: people choosing doctors and clinics in India. This records technical/product constraints and unresolved access questions; it is not a legal conclusion.

## Data access is the first gate

- **Places API (New) cannot supply an arbitrary business's complete review history.** Its `reviews` field returns at most five reviews, ordered by relevance. This is a selected sample, not a random sample. Inference: it cannot justify a clinic-wide manipulation percentage or robust review-burst analysis. [Official Place resource](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places)
- **Business Profile review pagination is an authenticated business-management route.** The endpoint supports 50 reviews per page and page tokens, requires business-management OAuth authorization, and only operates on a verified location. It is not a public all-business review API. [Official reviews.list reference](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.reviews/list)
- **API access carries significant content restrictions.** Google Maps Platform terms section 3.2.3 restricts scraping/export, review copying/storage, caching except specified exceptions, and use of Maps content to train, test, validate or fine-tune ML/AI models. Places policy allows indefinite place-ID storage and requires attribution, review-source links, and notice of sorting/filtering. Model inference should not be silently equated with permission to train or validate on Google content. [Platform terms](https://cloud.google.com/maps-platform/terms), [Places policies](https://developers.google.com/maps/documentation/places/web-service/policies)
- **Reading the browser page is a different access route, not an established policy exemption.** End-user Maps terms separately restrict copying, mass downloads/bulk feeds, and creating products/services based on Maps. User activation and local processing reduce collection and privacy exposure; they do not by themselves establish permission. Before relying on a DOM adapter, resolve whether the specific read/analyze/display workflow is permitted, or acquire an independently authorized data source. [Maps end-user terms](https://www.google.com/intl/en-GB_US/help/terms_maps/)

## Extension implementation constraints

- An MV3 extension must bundle executable JavaScript/WASM; remotely fetched JSON/data is distinguished from remote executable code. Keep runtime code packaged. [Remote hosted code policy](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code)
- `activeTab` provides temporary access after a user gesture. With `scripting`, it permits content-script injection without permanent all-site access. Choose user activation for the first desktop prototype. Add narrowly scoped optional host access only if an actual automatic workflow requires it. [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [Permission declarations](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions)
- Chrome Web Store requires the narrowest necessary permissions and user-data transparency; local-only handling is not a reason to skip all applicable privacy disclosures. [User-data FAQ and minimum permission requirements](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)
- **Desktop coverage must be explicit.** Google's documented phone installation flow is “Add to Desktop,” followed by installation on the computer; it is not a mobile runtime flow. A Chrome desktop extension also cannot run inside the native Google Maps phone app. Inference: ask whether desktop users are sufficient for the India pilot before committing to extension-only distribution. [Official install guide](https://support.google.com/chrome_webstore/answer/2664769?hl=en)

## Evidence and product wording

- The current Place resource includes `consumerAlert`, Google's own message when it detects suspicious review activity or policy violations. Preserve its specific wording and attribution when present; a policy-violation alert must not be rewritten as proof of purchased reviews. The reference does not establish nationwide Indian coverage or completeness, so absence is not a clean bill of health. [Official consumer alert schema](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places#ConsumerAlert)
- Google explicitly states that reviews are not verified, although it checks for and removes identified fake content. Neither publication nor removal status should be treated as a validated truth label for our classifier. [Places review policy](https://developers.google.com/maps/documentation/places/web-service/policies)
- Research identifies realistic labeled data as a bottleneck; work using Amazon data cannot establish accuracy on Indian clinic reviews. [Yao et al., RANLP 2017](https://arxiv.org/abs/1707.09406)
- A 2025 study reports deception-detection performance differences across models and contexts, across five languages and six cultural settings. This supports context-specific evaluation rather than a universal text-only detector claim. [Papantoniou et al., RANLP 2025](https://aclanthology.org/2025.ranlp-1.101/)
- **Recommended interpretation, pending validation:** show observable patterns, the exact supporting reviews, analyzed sample size, accessible coverage, and an “insufficient evidence” outcome. Repeated phrasing, many five-star reviews, or a short posting burst can have legitimate explanations. Do not present an unvalidated “fake probability,” “true star rating,” or inference about clinical competence.

## Decision

Conditional recommendation: a small, user-activated desktop MV3 side panel with local deterministic analysis and explicit evidence. WXT + TypeScript + React is an implementation candidate, not a solution to data permission or detection validity. Confirm the access route and desktop fit first; evaluate on independently authorized, representative Indian healthcare examples before adding a model or backend.
